CASE STUDY

🎮 EXPLORE THE FULL JOURNEY SHIPPED TO APP STORE 🍎 APP STORE

From a terminal Python script to a shipped iOS game — built from scratch through experimentation, iteration, and creative engineering.

App Store TestFlight Stick Fight Repo Artabillies Jug Repo First Dev Chat

🌱 Phase 1 — Terminal Origins

The journey started with Python scripts in the terminal: ASCII art, text-based rendering, and simple scripted interactions. These weren't just exercises — they established a design philosophy blending retro aesthetics with playful experimentation.

Early Explorations

  • ASCII image generation — Python scripts producing visual art in terminal environments
  • Stick-figure animations using Pygame with music and interactive movements
  • Terminal-based rendering and text-driven visual design
  • Early debugging: python vs python3, file path resolution, working directory context
Artabillies Jug Stick Fight

🎮 Phase 2 — Terminal Game Prototype

The core concept: move a player, avoid enemies, collect points — running entirely inside the terminal. Built with Python's curses for rendering and pygame.mixer for audio.

Core Mechanics

  • Player character, enemies, collectible dots, live score tracking
  • Real-time movement and reactions in terminal
  • Continuous dot spawning and enemy collision detection
  • Difficulty scaling — enemies increase in count and speed with score

Engineering Challenges Solved

  • _curses.error: add_wch() returned ERR — fixed with boundary clamping
  • Audio file path resolution — learned execution context and working directory behavior
  • Rendering crashes from drawing outside terminal bounds

🌐 Phase 3 — Terminal → Web Engine

The breakthrough transformation: porting the Python terminal game into a browser-based Canvas game with HTML5, CSS, and JavaScript.

Architecture Shift

  • Terminal rendering → HTML5 Canvas API
  • Python runtime → JavaScript
  • Local terminal → browser-based cross-platform engine
  • Game loop via requestAnimationFrame

Cross-Platform Input System

  • Mobile: tap-to-move with continuous vector-based motion
  • Desktop: click-to-move mirroring touch behavior
  • Keyboard: arrow keys and WASD with directional override
  • Unified control logic across all platforms

Audio Engine

  • Background DnB-style retro loop, gem pickup sounds, game over effects
  • Solved browser autoplay restrictions — audio triggered by user interaction
  • DOM audio element mismatch debugging and defensive playback checks

Critical Bug Fixes

  • Collision detection rewritten with full AABB bounding-box system for 360° accuracy
  • Null audio object errors fixed with DOM ID alignment and defensive checks
  • Responsive fullscreen canvas with dynamic resize support

🖥️ Phase 4 — UI Systems & Game Loop

The game grew into a complete arcade experience with multiple interface states and replayability systems.

Interface States

  • Start screen with title, rules, thematic instructions, and start button
  • Active game canvas with live HUD
  • Game over screen with score, high scores, and try-again flow
  • Top 3 high score system with sorted ranking
  • Clean state reset and restart loop

Expanded Features

  • Power-ups: speed boost, invincibility, score multipliers
  • Dynamic enemy mechanics — speed and quantity scale with progress
  • Retro monospace visuals with bright arcade color accents
  • Responsive design for phones, tablets, and desktops
